# Building and releasing

linux-labs ships as one noarch RPM. CI builds it on every push, and a version tag turns that build into a signed release in the dnf repository on GitHub Pages.

## The version

`rpm/linux-labs.spec` is the source of truth. Its `Version:` line is the release version, and the build script, the tarball name and the release check all read it from there. `Release: 1` has no `%{?dist}`: one RPM built on EL8 installs on EL8 and EL9.

## Building locally

```bash
scripts/build-rpm-linux.sh                    # on an EL8 host or container with rpm-build and sudo
scripts/build-rpm-linux.sh --deploy user@host # same, then scp and dnf reinstall on that host
```

The script reads `Name:` and `Version:` from the spec, then:

1. recreates `packaging/rpmbuild/SOURCES/<name>-<version>/` from `labs/` (without any `solve.sh`), `src/etc`, `src/usr`, `src/opt/linux-labs/lib` and `docs/student/*.md`
2. copies the spec into `packaging/rpmbuild/SPECS/`
3. tars the sources and runs `rpmbuild`
4. leaves the RPM in `packaging/rpmbuild/RPMS/noarch/`

It stops with an error when `docs/student/` holds no `*.md` file, because the spec installs those files as `/usr/share/doc/linux-labs/` (`%doc`).

Each lab ships `setup.sh`, `grade.sh`, `cleanup.sh`, `description.txt`, `task.txt` and `solution.md`. `%install` deletes any `solve.sh` that reaches the buildroot as a second guard and sets every `*.sh` under `/opt/linux-labs` to mode 0755. labctl is installed 0755; there is no setuid (the kernel ignores it on scripts, and sudo gives root). `%check` runs `visudo -cf` on the sudoers rule, which is why `sudo` is a BuildRequires.

`packaging/` is a gitignored local build directory (it also holds `test-logs/`). Edit `labs/`, `src/`, `docs/student/` and `rpm/linux-labs.spec`, never the copies under `packaging/`.

Without `--deploy` the script contacts no host. `--deploy root@10.0.0.149` copies the RPM to `/root/` on the author's personal test VM and reinstalls it there; ask the author before using it.

A build without an EL8 machine works in a container:

```bash
docker run --rm -v "$PWD":/src -w /src rockylinux/rockylinux:8 \
  bash -c 'dnf -y -q install rpm-build tar gzip sudo findutils && scripts/build-rpm-linux.sh'
```

## CI

`.github/workflows/rpm.yml` runs these jobs:

| Job | When | What |
|---|---|---|
| `check` | every push to `main`, every PR, every tag | `scripts/check-labs.sh` on `ubuntu-latest` with `SHELLCHECK=docker` |
| `build` | after `check` | `scripts/build-rpm-linux.sh` in a `rockylinux/rockylinux:8` container, uploads the unsigned RPM |
| `smoke` | after `build` | installs the RPM on Rocky 8 and Rocky 9: `labctl list`, `grading.sh` present, no `solve.sh` shipped, labctl mode 755, `visudo -c` |
| `release` | tags `v*` only | checks the tag against the spec `Version:`, signs the RPM, verifies the signature |
| `release-smoke` | tags `v*` only | installs the signed RPM on Rocky 9 with `gpgcheck=1` |
| `publish` | tags `v*` only | creates the GitHub Release and updates the dnf repo on `gh-pages` |

A tag that does not match `Version:` fails the `release` job, and nothing is published.

## Signing

`scripts/sign-rpm.sh` signs the RPM inside the `release` job. It reads two repository secrets:

- `RPM_GPG_PRIVATE_KEY`: the ASCII-armored private key
- `RPM_GPG_PASSPHRASE`: its passphrase

The key fingerprint is `2C8B8EF02609AF36359D2D7E603E53FE67BA2549`. The public half is committed as `pages/RPM-GPG-KEY-linux-labs`, and the `release` job imports it to check the signature with `rpm -K`. The script imports the private key into a temporary `GNUPGHOME`, passes the passphrase through a 0600 file in that directory and deletes the directory on exit.

## The dnf repository on GitHub Pages

The `publish` job checks out the `gh-pages` branch (or creates it on the first release) and runs `scripts/update-pages.sh`, which writes:

- `rpm/*.rpm` and `rpm/repodata/`: the dnf repository, refreshed with `createrepo_c --update`; every released RPM is kept
- `install`: a copy of `pages/install.sh`
- `linux-labs.repo` and `RPM-GPG-KEY-linux-labs`, from `pages/`
- `index.html`, from `pages/`
- `catalog.html`: the lab catalog, generated by `scripts/gen-catalog.sh --html`; it is not committed to `main`
- `.nojekyll`

The job commits and pushes `gh-pages`. GitHub Pages serves the branch at https://matej-basic.github.io/linux-labs/. Pages has to be enabled once in the repository settings (Settings, Pages, source "Deploy from a branch", branch `gh-pages`, folder `/`).

## Release steps

1. Bump `Version:` in `rpm/linux-labs.spec` and add a `%changelog` entry.
2. Run `SHELLCHECK=docker scripts/check-labs.sh` and build the RPM once locally.
3. Commit and push to `main`, then wait for the `check`, `build` and `smoke` jobs.
4. Tag and push the tag:

   ```bash
   git tag v1.2.0
   git push origin v1.2.0
   ```

5. Check that the run finished, that the GitHub Release has the RPM, and that `sudo dnf upgrade linux-labs` on a test VM picks up the new version.

Runtime test results for the release (for example "Verified on Rocky 8.7 workstation: N of 55 PASS") go into the release notes, not into git.
