OBJECTIVE
  Write the Ansible role webserver with Jinja2 templates, per-host
  variables and a handler, and apply it to the web servers on nodes 2
  and 3 with a playbook.

TOPOLOGY
  Log in to node 1 from the workstation over SSH, as the user that the
  lab configuration uses for the nodes (SSH_USER, opsadmin in the
  classroom). Do all work on node 1 as that user, called "your user"
  below. Nodes 2 and 3 are the managed nodes.

     workstation
          |
          | SSH as your user
          |
     node 1  {{NODE1_IP}}
     Ansible control node, project directory ~/ansible-lab
          |
          | SSH as the user ansible
          |
     +----+-----------------------+
     |                            |
     node 2                       node 3
     {{NODE2_IP}}                 {{NODE3_IP}}
     managed node                 managed node

PREREQUISITES
  - Multi-node labs are enabled with at least 3 nodes
    (NODE_COUNT={{NODE_COUNT}}).
  - The lab starts where ansible-01 ends, without its playbook. labctl
    start sets this up:
    - ansible-core is installed on node 1.
    - ~/ansible-lab of your user on node 1 holds ansible.cfg and
      inventory and nothing else. ansible.cfg sets the inventory, the
      remote user ansible, the private key ~/.ssh/ansible_lab and
      privilege escalation with sudo.
    - The inventory has the group webservers with the hosts
      {{NODE2_IP}} and {{NODE3_IP}}.
    - The user ansible on nodes 2 and 3 accepts the key and may run
      every command with sudo without a password.
    - httpd is not running on nodes 2 and 3.
  - The nodes reach the Rocky Linux package repositories.

TASKS
  1. The role webserver is in ~/ansible-lab/roles/webserver. It has the
     files tasks/main.yml, handlers/main.yml and defaults/main.yml, and
     the templates templates/index.html.j2 and
     templates/webserver.conf.j2.
  2. The role defaults set the variable web_greeting to the value
     Hello from Ansible.
  3. The file ~/ansible-lab/group_vars/webservers.yml sets
     web_greeting to Welcome to the web farm for the group webservers.
  4. The file ~/ansible-lab/host_vars/{{NODE3_IP}}.yml sets
     web_greeting to Welcome to the staging server for node 3 only.
  5. The tasks of the role use the module template for both files. The
     role has a handler in handlers/main.yml that restarts the service
     httpd. The task that deploys webserver.conf notifies it.
  6. The playbook ~/ansible-lab/site.yml has a play for the group
     webservers that applies the role webserver. It passes the syntax
     check.
  7. A run of site.yml in check mode completes without failures and
     reports no changes on nodes 2 and 3.
  8. On nodes 2 and 3 the role has reached this state:

       - the package httpd is installed, and the service httpd is
         enabled at boot and running
       - /var/www/html/index.html holds exactly two lines: the value
         of web_greeting for the node, then the words Served by and
         the short host name of the node from its facts, for example:

           Welcome to the web farm
           Served by serverb

       - /etc/httpd/conf.d/webserver.conf holds exactly two lines: the
         comment line # Managed by Ansible, then ServerName and the
         address of the node as it appears in the inventory

  9. When webserver.conf on node 2 differs from the template, a run of
     site.yml puts it back and restarts httpd on node 2 through the
     handler.

PRACTICE (not graded)
  - Run site.yml twice and compare the changed counts. Watch when the
    handler runs.
  - Override web_greeting on the command line with an extra variable
    and compare the precedence with host_vars.

NOTES
  - Ansible looks for roles in the directory roles next to the
    playbook. It reads group_vars and host_vars next to the inventory
    and next to the playbook.
  - Variables in the role defaults have the lowest precedence. Group
    variables override them and host variables override both.
  - A handler runs once at the end of the play, and only when a task
    that notifies it reports a change.
  - Only the modules of ansible-core (ansible.builtin) are available.
    The module documentation is in ansible-doc.
  - Rocky Linux 8 ships ansible-core 2.16 and Rocky Linux 9 ships 2.14.
    The task works the same with both.
  - labctl reset removes ~/ansible-lab, the SSH key and known hosts
    that the lab added for your user on node 1, the user ansible with
    its sudo rule, and every package the lab installed on the nodes.

GRADING
